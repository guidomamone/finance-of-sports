## 1. El formato

`<slug>-<iso2>`: el slug de siempre (minúsculas y dígitos, sin guiones) + guion + el país en ISO 3166-1 alfa-2 minúscula, **el mismo código que `country`
de `data/clubs.js`** (`elche-es`, `corinthians-br`, `boca-ar`). Es la convención que ya rige para todo club nuevo (`audit.js`, `clubid-sin-pais`, hoy P2);
este to-do la extiende a los heredados.

Reglas que quedan escritas (en `Admin/CONVENCIONES-DATOS.md`, "Identidad del club"):

- Un id **nunca se reutiliza ni se borra de la historia**: si un club cambia de id, el viejo pasa al mapa de alias y queda para siempre.
- Un alias apunta a un id vivo (sin cadenas) y ningún id vivo es también alias.
- El sufijo de país no cambia si el club cambia de liga o de país de juego; es el `country` de `clubs.js` (el país de la entidad que publica).

Medido: 319 clubes en `data/clubs.js`; 278 ya cumplen; **41 cambian**. Cero colisiones (ningún `<viejo>-<iso2>` existe) y ningún id vivo empieza con
`<viejo>-` (importa para reescribir los sourceIds, ver 3).

## 4. Cómo sigue funcionando un id viejo

**Un solo mapa** `data/club-aliases.js`: `window.CLUB_ALIASES = { boca: 'boca-ar', river: 'river-ar', … }` (41 entradas, se publica y entra a
`datapackage.json` como dato abierto, porque quien guardó un id de la API de mañana lo necesita). Lo escribe el script; `audit.js` suma `alias-roto`
(P1: apunta a un id inexistente, es cadena, o el alias es también un id vivo) y `clubid-sin-pais` pasa a P1 (hoy P2) sin lista de heredados.

**En el sitio** (`js/principal.js`, carga antes que `clubs.js` quede en uso): `resolverClubId(id)` = `CLUB_ALIASES[id] || id`. Se aplica en
`aplicarURL` a `club`, en `ladoDeURL` a cada club de `a`/`b`, al leer `fos_club` de `localStorage` y al reabrir una búsqueda guardada de Mi cuenta.
Después de resolver, `escribirURL('replace')` ya reescribe la URL con el id nuevo: el link viejo abre y deja de serlo. Los links viejos de
`?club=` no pueden redirigirse en el servidor (es query), por eso el alias vive en el sitio y **no se borra nunca**.

**En el servidor** (`fuentes/` es lo único con ruta por club y la indexa Google): `netlify.toml` suma 41 reglas
`/fuentes/<viejo>.html → /fuentes/<nuevo>.html`, 301 (y la forma sin `.html`). Las genera el mismo script entre dos marcas
(`# ids-alias:inicio/fin`) para que no se editen a mano. El `sitemap.xml` ya sale con las rutas nuevas.

**En las tools**: `data-clubes.js` exporta `normalizarId(id)` (con el mismo mapa, leído de `data/club-aliases.js`). Lo usan las tools que reciben
`--club <id>` o leen un registro histórico por id. Un id viejo en un argumento corre y avisa "usá boca-ar".
